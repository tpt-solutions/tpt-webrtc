# tpt-webrtc Design Specification

## Mission

Build a complete, production-ready WebRTC implementation in pure Rust that provides:
- **Full Protocol Stack**: ICE, STUN, TURN, DTLS-SRTP, RTP/RTCP, SCTP data channels
- **Modern Codecs**: AV1-first, VP8/VP9, Opus audio, with hardware acceleration
- **Zero libwebrtc Dependency**: No Google C++ code, no hidden patent traps, no build hell
- **Formally Verified State Machines**: ICE and DTLS handshakes proven correct via `tpt-telos`
- **Async-Native Architecture**: Built on `tokio` for high-concurrency server and client use

This is not a wrapper around libwebrtc. This is a ground-up reimplementation that replaces Google's 2-million-line C++ behemoth with a memory-safe, MIT-licensed, formally verified alternative.

---

## The Problem We're Solving

### The libwebrtc Monopoly
Google's `libwebrtc` is the de facto standard for WebRTC, but it has fundamental flaws:
- **2 million lines of C++**: A memory safety nightmare (Heartbleed-style vulnerabilities are inevitable)
- **Build hell**: Requires GN build system, dozens of dependencies, and is notoriously difficult to embed
- **Google-controlled**: Not truly open-source; Google dictates the roadmap and can change licensing terms
- **Hidden patent traps**: While BSD-3-Clause, it includes Google's patent grants that may not transfer to derivatives
- **No formal verification**: Critical state machines (ICE, DTLS) are not mathematically proven correct

### The Licensing Minefield
WebRTC involves multiple patent-encumbered technologies:
- **H.264**: MPEG-LA patent licensing (royalty-bearing for distributors)
- **VP8**: Google's patent grant (but unclear if it extends to derivatives)
- **VP9**: Open, but Google-controlled
- **AV1**: Alliance for Open Media (AOM) patent pool, royalty-free, truly open

**Our Strategy**: AV1-first, VP9 fallback, avoid H.264 entirely. This eliminates the patent royalty risk.

impl HardwareEncoder {
    pub fn new(backend: HardwareBackend, codec: VideoCodec) -> Result<Self, CodecError> {
        let encoder = match backend {
            HardwareBackend::NvEnc => Box::new(NvencEncoder::new(codec)?),

            HardwareBackend::VideoToolbox => Box::new(VideoToolboxEncoder::new(codec)?),

        };
        Ok(Self { backend, encoder })
    }
}

    layers: Vec<SimulcastLayer>,
}

pub struct SimulcastLayer {
    pub rid: String,
    pub width: u32,
    pub height: u32,
    pub max_bitrate: u32,
    pub encoder: Box<dyn VideoEncoder>,
}

impl SimulcastEncoder {
    pub fn encode(&mut self, frame: &VideoFrame) -> Result<Vec<(String, Vec<EncodedPacket>)>, CodecError> {
        let mut results = Vec::new();
        for layer in &mut self.layers {
            let scaled_frame = self.scaler.scale(frame, layer.width, layer.height)?;
            let packets = layer.encoder.encode(&scaled_frame)?;
            results.push((layer.rid.clone(), packets));
        }
        Ok(results)
    }
}

Document clearly that H.264 is not supported due to patent licensing

The tpt-telos Advantage
This is where your agentic compiler becomes a massive differentiator.
The ICE and DTLS state machines are the most critical and error-prone parts of WebRTC. Traditional implementations (like libwebrtc) have had numerous CVEs due to state machine bugs.
With tpt-telos, you can write formal contracts:

#[requires(agent.state == IceState::Gathering)]
#[ensures(result.is_ok() ==> agent.state == IceState::Waiting || agent.state == IceState::Failed)]
#[ensures(result.is_err() ==> agent.state == IceState::Failed)]
pub fn gather_candidates(agent: &mut IceAgent) -> Result<Vec<IceCandidate>, IceError>;
